# Warm Vibe Bistro: restaurant ordering and management site

Django 6 project (Python 3.12+). Customers browse the menu, order for pickup (paid through Stripe Checkout), and book tables. Staff run the business from `/dashboard/`.

## Project map
- `restaurant_site/`: settings, root urls (the home page view lives in `urls.py`), wsgi/asgi
- `menu/`: Category, MenuItem, AddOn, Tag, and the public menu pages
- `orders/`: session cart (`cart.py`), checkout, Stripe webhook, PromoCode, order emails (`emails.py` + `email_templates/`)
- `reservations/`: table booking; parties of 4 or fewer auto-confirm
- `dashboard/`: staff-only area, one `*_views.py` per section; roles live in `StaffProfile` (owner > manager > staff); decorators in `decorators.py`
- `static/`: our CSS/JS source. `staticfiles/` is GENERATED by collectstatic: never edit it.

## Commands (project root, virtual environment active)
- Setup (Windows PowerShell): `python -m venv venv`, then `venv\Scripts\Activate.ps1`, then `pip install -r requirements.txt`
- Required env var: `SECRET_KEY` (no default; Django refuses to start without it). `DEBUG` defaults to False (safe), so for local work put `DEBUG=True` in `.env`. All variables are listed in `.env.example`.
- Optional env vars: `DATABASE_URL` (default sqlite), `REDIS_URL`, `STRIPE_*`, `SENDGRID_API_KEY`, `CLOUDINARY_*`
- Run: `python manage.py migrate`, then `python manage.py runserver`
- Check: `python manage.py check` and `python manage.py makemigrations --check --dry-run`
- Tests: `python manage.py test` (or `python manage.py test orders`). It automatically uses `restaurant_site/test_settings.py`: in-memory database, in-memory email, dummy Stripe keys. Needs no environment variables.
- Deploy: Render runs `build.sh` (collectstatic, migrate, createsu, create_staff_profile)

## How the important flows work
- Cart: kept in the session under key `cart` (`orders/cart.py`). Prices are copied into the session when an item is added.
- Checkout: `checkout_view` saves a pending Order, remembers it for this browser, then redirects to Stripe Checkout. Stripe sends the customer to `payment_success` and also calls `stripe_webhook`. Both paths verify with Stripe and then call `confirm_order_paid()` in `orders/services.py`, which is safe to call repeatedly.
- Privacy of customer pages: `restaurant_site/access.py` (`grant_access`, `has_access`) remembers which orders and reservations this browser created. Pages for them return 404 to everyone else.
- Staff login is `dashboard:login`. Every dashboard view needs `@staff_required`, plus `@manager_required` or `@owner_required` where needed.

## Rules for working here
- Money is `Decimal`. Never `float`.
- An order counts as paid only when Stripe's signed webhook says so.
- Any view that takes an id or email must check the requester may see that record.
- Use `django.utils.timezone`, not `date.today()`.
- No bare `except Exception`. Never show exception text to users.
- Never edit an already-applied migration; create a new one.
- Never read, print, or commit `.env` files. Use `.env.example` for placeholders.
- Security settings live in `settings.py` under `if not DEBUG`. Never weaken them to make something work locally; tests have their own overrides in `test_settings.py`.
- Staff login is rate limited per account (`@ratelimit` in `dashboard/views.py`). Redirect targets from user input must pass `url_has_allowed_host_and_scheme`.
- Ask before adding a dependency.
- Every bug fix starts with a failing test (use the test-writer agent), then the fix, then the whole suite.
- Use plan mode before changing payments, login, roles, or settings.
- Before saying "done": `python manage.py check` passes and the relevant tests pass. State what you ran and what you saw.
